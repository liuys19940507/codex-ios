# 历史分页与右上角导航验证

## 复现与修复

用户报告“源潜-上下板机项目”无法读取较早记录，并要求把固定底部的任务、连接、设置移到右上角“…”菜单。

真实只读排查发现两个不同现象：

- 会话的17轮记录已完整进入缓存，但桥接错误地把原生 `itemsBackwardsCursor` 的重新读取入口当作初始轮次页之后的续页。前33页返回新记录后，后续页面开始50条全部重复。现在使用初始轮次页自己的 `nextCursor`，完整页结束时不会继续提示较早记录。
- 本次观察的首次较早页新增50条原始记录，却没有新增顶层消息行，因为它们都属于已经折叠的同一轮处理过程。客户端现在显示实际新增数量，并在出现更早消息行时定位到它；处理记录仍从“查看处理过程”展开。

桥接对更早轮次一次读取一轮，将超出50条的部分缓存后分页返回；并发读者重用已缓存记录，正在生成的输出和当前同步周期保持优先。回归覆盖旧同步周期响应、空轮次、重复游标以及在第20次原生读取才出现有效数据的边界。

## 已执行的服务端验证

- 最初5项回归全部实际失败后修复；同步周期竞态另有一次实际失败后通过。
- 一次独立检查发现第20页数据在遍历预算耗尽时被遗漏。新增终止/非终止第20页回归实际复现“预期50、实际0”，修复后通过；另有受控的并行读者按相反顺序完成测试。
- 全部126项 Node 测试及 TypeScript 检查通过。服务端仅更新了验证身份后的桥接进程，共享 Codex app-server 的进程、启动时间和服务身份保持原值。
- 更新后，对同一条正在运行的真实会话连续读取35页，得到1787条唯一历史，重复数为0，最后游标为空。记录数是本次观测值，运行中的会话仍可能继续增加。
- 附件目录的沙箱组读权限、私有父目录及令牌权限保持原有边界。
